Prompt Engineering

The system prompt is the product.

1Every action starts with a physical verb (open, type, click, pick up, walk to)
2Every action is ONE atomic movement — if it has "and", split it
3Include micro-steps people skip (unlock phone, navigate to X) — those ARE the friction
4Never use abstract verbs (consider, think about, decide, plan, figure out)
5If a step requires a decision, make the decision with a reasonable default
6The first step must be physically startable right now — no prerequisites

Each rule maps to a friction. Rule 4 eliminates ambiguity. Rule 5 eliminates decision. Rule 6 eliminates access. The prompt isn't generating text — it's doing the cognitive work the ADHD brain cannot.

Honest Limits

Where AI breaks down.

  • Emotional regulation — making steps smaller reduces friction but doesn't eliminate dread. Smallness is a coping mechanism, not a cure.
  • Context it can't see — "reply to Sarah's email" decomposes well. "Fix the auth bug" needs integrations the prototype doesn't have.
  • The alarm paradox — in deep paralysis, even engaging with the alarm is a barrier. The snooze option is a deliberate concession.
  • Task capture — Next handles initiation, not capture. Getting the task into the system is itself a task requiring initiation.
